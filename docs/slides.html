4. Critical Point 1: Closed-Network Citation Integrity

Eliminating dangling foreign keys and phantom graph components in bibliometric graphs.

The Challenge: Phantom References

Scholarly papers cite thousands of historical and cross-domain works outside any finite sampling boundary. In our pilot extraction:

8,850
Dangling External References

Allowing external references into PostgreSQL triggers foreign-key constraint violations. In Neo4j, it creates thousands of empty "leaf" nodes that distort graph centrality algorithms.

The Closed-Network Boundary Rule

The ETL mathematically filters citation edges to those within the closed retained corpus:

# run_etl.py citation reconciliation retained_work_ids = set(works.keys()) citations = [ (citing, cited) for citing, cited in raw_refs if citing in retained_work_ids and cited in retained_work_ids and citing != cited # Prune self-loops ]
  • ✓ Zero foreign-key violations in PostgreSQL.
  • ✓ Guaranteed reachability across multi-hop graph traversals.
  • ✓ Prunes work self-citations while keeping author self-citations.

5. Critical Point 2: Work-Contextual Affiliations

Preventing "timeless" affiliation distortion across relational and graph models.

The Conceptual Trap

Researchers change jobs, hold dual appointments, or write preprints before switching institutions.

Flawed Direct Edge:
(:Author)-[:AFFILIATED_WITH]->(:Institution)
Implies a timeless association. An author at Stanford in 2020 and Google in 2023 would falsely attribute their 2020 papers to Google!

The Contextual Solution

Affiliations are treated strictly as events within the context of a work:

-- Relational: Ternary association CREATE TABLE affiliations ( work_id TEXT, author_id TEXT, institution_id TEXT, PRIMARY KEY (work_id, author_id, institution_id), FOREIGN KEY (work_id, author_id) REFERENCES authorships(work_id, author_id) ); // Neo4j: Relationship property (:Author)-[:AFFILIATED_WITH {work_id: 'W123'}]->(:Institution)

Preserves exact paper authorship provenance across both databases.

Database Paradigm 1

6. PostgreSQL Relational Model (3NF)

Entity integrity, composite keys, and relational index optimization.

Schema Highlights (`schema: openalex`)

  • ★
    Normalized 3NF Entities: Separate tables for works, authors, institutions, sources, and topics with explicit foreign keys.
  • ★
    Integrity Constraints: Check constraints on non-negative citations, publication years, and valid role types.
  • ★
    Composite Primary Keys: Fast natural indexing on junction tables like (work_id, author_id).

Engineered Indexes (`01_indexes.sql`)

CREATE INDEX idx_works_year_type ON works (publication_year, work_type); CREATE INDEX idx_authorships_author ON authorships (author_id); CREATE INDEX idx_affiliations_inst ON affiliations (institution_id); CREATE INDEX idx_citations_cited ON citations (cited_work_id);

Relational ER Structure

WORKS (work_id, title, year, citations, type)
├── (1:N) ── AUTHORSHIPS (work_id, author_id)
│ ├── (N:1) ── AUTHORS (author_id, name)
│ └── (1:N) ── AFFILIATIONS (work_id, author_id, inst_id)
│ └── (N:1) ── INSTITUTIONS (institution_id)
├── (1:N) ── WORK_TOPICS (work_id, topic_id, score)
│ └── (N:1) ── TOPICS (topic_id, hierarchy)
├── (1:N) ── WORK_SOURCES (work_id, source_id)
│ └── (N:1) ── SOURCES (source_id, venue)
└── (1:N) ── CITATIONS (citing_work_id, cited_work_id)

Loaded in <1 second via streaming PostgreSQL COPY protocol.

Database Paradigm 2

7. Neo4j Labeled Property Graph (LPG)

Index-free adjacency and expressive topological relationship matching.

Graph Topology & Schema

Every entity becomes a first-class Node; every junction becomes a directed, typed, and attributed Relationship:

(:Author)-[:AUTHORED {author_order, is_corresponding}]->(:Work) (:Author)-[:AFFILIATED_WITH {work_id}]->(:Institution) (:Work)-[:HAS_TOPIC {score, is_primary_topic}]->(:Topic) (:Work)-[:PUBLISHED_IN {location_role}]->(:Source) (:Work)-[:CITES]->(:Work)
  • ✓ Unique ID Constraints: Range indexes on (n.id) for all node labels.
  • ✓ Batch Merge Ingestion: UNWIND $rows AS row ... MERGE pattern.

Why Graph for Scholarly Networks?

O(1)
Per-Hop Traversal (Pointer Chasing)

In relational tables, traversing citations requires repeated B-tree index lookups on the citations table. In Neo4j, each node directly stores memory pointers to its adjacent edges, making variable-length path traversal immune to global graph size.

Database Paradigm 3

8. Relational Data Warehouse (Star Schema)

Dimensional Fact Model (DFM) with conformed dimensions and multivalued bridges.

Dimensional Fact Architecture

dim_date    dim_source    dim_work_type
      \            |            /       
fact_work (Grain: 1 work)
      /            |            \       
bridge_topic   bridge_author   bridge_institution
      |            |            |       
dim_topic    dim_author    dim_institution

Grain: Exactly one retained work. Measures: publication_count = 1 (additive), cited_by_count (semi-additive).

The Multivalued Bridge Policy

  • ★
    Preserving Fact Granularity: Prevents exploding fact_work rows when papers have 10 authors or 5 topics.
  • ✓
    Full Association Accounting: A multi-topic work contributes 1 publication count to each assigned topic's association measure.
  • !
    No Double-Counting: Corpus-level totals query fact_work alone; bridge tables are used only when slicing by multi-valued dimensions.
Expressiveness Benchmark

9. Query Expressiveness: SQL vs. Cypher

Analytical Question 5: Directed Citation Paths of Length 2 to 4 Hops.

PostgreSQL (Recursive CTE) 25 Lines · Complex
WITH RECURSIVE citation_paths AS ( SELECT c.citing_work_id AS start_id, c.cited_work_id AS curr_id, ARRAY[c.citing_work_id, c.cited_work_id]::TEXT[] AS path, 1 AS hops FROM citations c WHERE c.citing_work_id = :start_id UNION ALL SELECT p.start_id, c.cited_work_id, p.path || c.cited_work_id, p.hops + 1 FROM citation_paths p JOIN citations c ON c.citing_work_id = p.curr_id WHERE p.hops < 4 AND NOT c.cited_work_id = ANY (p.path) -- Cycle guard ) SELECT start_id, curr_id, hops, path FROM citation_paths WHERE hops BETWEEN 2 AND 4;
Neo4j (Cypher Pattern) 3 Lines · Elegant
MATCH (start:Work {id: $start_id}) MATCH p = (start)-[:CITES*2..4]->(target:Work) RETURN length(p) AS hops, [n IN nodes(p) | n.id] AS path;
Expressiveness Evaluation:

Cypher handles variable-length paths natively with automatic path cycle detection. SQL requires explicit array concatenation, membership checks, and recursive memory tables.

10. Aggregation & Multi-Entity Joins

Analytical Questions 2B & 4: Institutional Productivity and Collaborative Pairs.

Q4: Institutional Co-authorship Pairwise Joins

Finding which pairs of institutions collaborated on works in year 2020:

// Neo4j: Symmetric multi-hop pattern MATCH (a1:Author)-[af1:AFFILIATED_WITH]->(i1:Institution) MATCH (a1)-[:AUTHORED]->(w:Work {id: af1.work_id, publication_year: 2020}) MATCH (a2:Author)-[af2:AFFILIATED_WITH]->(i2:Institution) MATCH (a2)-[:AUTHORED]->(w) WHERE i1.id < i2.id // Unordered pair deduplication WITH i1, i2, collect(DISTINCT w) AS works RETURN i1.display_name, i2.display_name, size(works) AS collab_count ORDER BY collab_count DESC;
Q2B: Warehouse vs. 3NF Slicing Star Schema Advantage

Calculating institutional productivity and citation impact:

-- Warehouse: 1 bridge join + pre-aggregated measures SELECT i.display_name, SUM(f.publication_count) AS works, SUM(f.cited_by_count) AS total_citations FROM fact_work f JOIN bridge_work_institution bwi ON bwi.work_key = f.work_key JOIN dim_institution i ON i.institution_key = bwi.institution_key GROUP BY i.institution_id, i.display_name ORDER BY works DESC;

3NF requires an expensive SELECT DISTINCT work_id, institution_id FROM affiliations subquery. The warehouse executes via integer keys and sequential scan.
